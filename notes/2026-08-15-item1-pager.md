## 2. File-by-File Technical Breakdown

### A. `include/pg/constants.h`
Defines core physical storage constants used across the database engine.

```cpp
#pragma once
#include <cstdint>
#include <cstddef>
#include <limits>

namespace pg {
    constexpr size_t PAGE_SIZE = 8192; // 8192 bytes (8KB)
    using page_id_t = uint32_t;
    constexpr page_id_t INVALID_PAGE_ID = std::numeric_limits<page_id_t>::max();
} // namespace pg
```

- **`PAGE_SIZE`**: Fixed to $8192$ bytes ($8\text{ KB}$). Every read, write, and allocation operation on disk operates in exact multiples of $8192$ bytes.
- **`page_id_t`**: 32-bit unsigned integer representing 0-indexed page positions in table files ($0, 1, 2, \dots$).

### B. `include/pg/pager.h`
Provides the RAII binary file manager abstraction.

```cpp
#pragma once
#include "pg/constants.h"
#include <fstream>
#include <string>
#include <memory>
#include <stdexcept>

namespace pg {

class Pager {
public:
    explicit Pager(const std::string& filepath);
    ~Pager();

    // Disable copying to enforce single file handle ownership
    Pager(const Pager&) = delete;
    Pager& operator=(const Pager&) = delete;

    // Support move operations
    Pager(Pager&& other) noexcept;
    Pager& operator=(Pager&& other) noexcept;

    static std::unique_ptr<Pager> open(const std::string& filepath);

    page_id_t allocate_page();
    void read_page(page_id_t page_id, void* out_buffer);
    void write_page(page_id_t page_id, const void* in_buffer);

    size_t num_pages() const;
    void flush();
    void close();
    bool is_open() const;
    const std::string& filepath() const { return filepath_; }

private:
    std::string filepath_;
    mutable std::fstream stream_;
    size_t num_pages_{0};

    void update_num_pages();
};

} // namespace pg
```

Key Design Principles:
1. **Single File Handle Ownership**: Copying is deleted (`delete`) to prevent race conditions or corrupted stream states from multiple instances sharing a file handle.
2. **RAII**: Destructor automatically flushes and closes the underlying `std::fstream`.
3. **Move Semantics**: Supported so `Pager` instances can be transferred between buffer pool components or memory managers.

### C. `src/pager.cpp`
Implements the seek math, file allocations, and bounds-checking logic.

#### Key Mechanics:
1. **File Opening & Creation**:
   Tries opening the file in binary read/write mode (`std::ios::in | std::ios::out | std::ios::binary`). If the file does not exist, it creates a blank file via `std::ofstream` first, then re-opens the `std::fstream`.

2. **Page Count Calculation**:
   ```cpp
   void Pager::update_num_pages() {
       stream_.clear();
       stream_.seekg(0, std::ios::end);
       auto file_size = stream_.tellg();
       if (file_size % PAGE_SIZE != 0) {
           throw std::runtime_error("Corrupted database file: size not a multiple of 8KB");
       }
       num_pages_ = file_size / PAGE_SIZE;
   }
   ```

3. **Page Allocation (`allocate_page()`)**:
   Calculates `new_page_id = num_pages_`. Seeks to offset `new_page_id * PAGE_SIZE`, appends a zero-filled $8192$-byte vector, flushes, and increments `num_pages_`.

4. **Random Page Disk Access (`read_page` & `write_page`)**:
   - Computes seek byte offset:
     $$\text{Offset}(p) = p \times 8192 \text{ bytes}$$
   - Clears stream state flags (`stream_.clear()`).
   - Seeks read pointer `seekg(...)` or write pointer `seekp(...)`.
   - Reads/writes exactly $8192$ bytes.
   - Throws `std::out_of_range` if $p \ge \text{num\_pages\_}$.

## 5. Quiz Diagnostics & Graded Mechanics

### Q1 · Page Offset Calculation (`PAGER-OFFSET`)
- **Question**: Where does Page $3$ live on disk?
- **Answered**: Option 3 ($\text{Offset } 24576$, bytes $[24576, 32767]$) ✅
- **Mechanism**:
  $$\text{Byte Offset} = \text{page\_id} \times \text{PAGE\_SIZE} = 3 \times 8192 = 24576$$
  - Page 0: $[0, 8191]$
  - Page 1: $[8192, 16383]$
  - Page 2: $[16384, 24575]$
  - Page 3: $[24576, 32767]$
- **Distractor note**: Option 2 ($32768$) corresponds to $4 \times 8192$, which occurs if one mistakenly treats pages as 1-indexed rather than 0-indexed.

---

### Q2 · C++ `std::fstream` State Bits (`STREAM-STATE`)
- **Question**: Why call `stream_.clear()` before `seekg()`/`seekp()`?
- **Answered**: Option 3 ❌ (Misconception: confused `clear()` with buffer flushing / `fsync()`).
- **Correct Mechanism**:
  In C++ standard I/O (`std::basic_ios`), `clear()` resets stream state flags (`eofbit`, `failbit`, `badbit`).
  When `update_num_pages()` seeks to the end or reads to the end of a file, `eofbit` is raised. 
  
  **The C++ Gotcha**: Once any error/EOF bit is set on `std::fstream`, **all subsequent seek and read/write calls become silent no-ops**. The file pointer will refuse to move and `read()` will read $0$ bytes without throwing an exception unless `stream.clear()` is called first.
  - `clear()` = resets error state bits in memory.
  - `flush()` = flushes user-space stream buffer to OS kernel.

---

### Q3 · Resource Ownership & Concurrency (`RAII-OWNERSHIP`)
- **Question**: Why delete copy constructors (`Pager(const Pager&) = delete`)?
- **Answered**: Option 2 ✅
- **Mechanism**:
  Each `Pager` holds internal state in RAM: `num_pages_`, in-memory stream buffers, and OS file descriptor offsets. If two instances manage the same file independently, Instance A allocating a page does not notify Instance B. Instance B's `num_pages_` will be stale, causing Instance B to write over Instance A's page at the same offset. Single-owner semantics (`unique_ptr` / move-only) are mandatory.
