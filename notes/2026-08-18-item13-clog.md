## 2. The Problem CLOG Solves

In Items 1–12:
- `TransactionManager` kept transaction commit/abort statuses in an in-memory `std::unordered_map<tx_id_t, TransactionStatus>`.
- Upon crash or engine restart, this map was lost and all transactions appeared `IN_PROGRESS`, requiring a slow, full WAL replay to discover which transactions committed.

**CLOG (`pg_xact/`)** provides a compact, persistent on-disk bitmap where each transaction status is encoded in exactly **2 bits**:

```text
               8KB CLOG PAGE (32,768 Transactions per Page)
 ┌──────────────────────────────────────────────────────────────────────────┐
 │ Byte 0: [ Tx 3 (2b) ][ Tx 2 (2b) ][ Tx 1 (2b) ][ Tx 0 (2b) ]             │
 │ Byte 1: [ Tx 7 (2b) ][ Tx 6 (2b) ][ Tx 5 (2b) ][ Tx 4 (2b) ]             │
 │ ...                                                                      │
 │ Byte 8191: [ Tx 32767 ][ Tx 32766 ][ Tx 32765 ][ Tx 32764 ]             │
 └──────────────────────────────────────────────────────────────────────────┘
```

### 2-Bit Status Encoding:
- `00` = `IN_PROGRESS`
- `01` = `COMMITTED`
- `10` = `ABORTED`
- `11` = `SUB_COMMITTED` (subtransactions)

## 3. Math & Page Indexing

For any arbitrary 64-bit transaction ID `tx_id`:
- **Page ID**: $\text{page\_id} = \lfloor \frac{\text{tx\_id}}{32768} \rfloor$
- **Byte Offset**: $\text{byte\_offset} = \lfloor \frac{\text{tx\_id} \pmod{32768}}{4} \rfloor$
- **Bit Shift**: $\text{bit\_shift} = (\text{tx\_id} \pmod 4) \times 2$
